## 实体设计

- **必须**统一使用 `defineEntity + class + setClass()`，禁止混用其他实体定义方式。
- Entity **必须**只描述持久化结构，API **必须**使用 DTO 或结果类型，禁止直接返回完整 Entity。
- **禁止**创建物理外键，必须同时保留全局配置和关系级别保护。
- **必须**保留 ORM 的关系能力，禁止为了避免隐式写入而删除必要的关系定义。
- `ManyToOne`、`OneToMany`、`ManyToMany`、`OneToOne`、`mappedBy`、`inversedBy` **可以**按实际读取方向使用。
- 每个关系**必须**显式使用空 `.cascade()`，禁止非空 cascade 和 orphan removal。
- 只保存当前关系且没有业务字段的纯关联表**必须**使用复合主键和物理删除，禁止添加独立 ID、时间戳和软删除字段。
- 包含状态、有效期、审批或其他业务字段的关系**必须**使用独立 pivot Entity，并按业务决定是否软删除。
- 关系列**必须**根据实际查询建立索引，已有复合索引或唯一索引可以覆盖时禁止重复建索引。
- 软删除数据的唯一约束和索引**必须**限定在有效数据范围。

## 读写分离

- ORM 关系**必须允许**用于查询、过滤、populate、JOIN、select-in、集合读取和数量统计。
- ORM 关系**禁止**承担隐式业务写入；关系新增、解除、事务和锁必须由专用 Service 显式处理。
- Service **可以**给关系属性赋值，但关系对象必须已经校验或具有明确主键。
- **禁止**使用集合的 `add`、`remove`、`set`、`removeAll` 修改关系。
- **禁止**通过嵌套 `em.assign()` 修改关系。
- 多对多写入**必须**通过专用关系 Service 操作 pivot Entity 或 QueryBuilder。
- 纯关联更新**必须**计算新增和移除差异，禁止无条件全删全建。
- 部分加载的集合**必须**视为只读。

## 查询

- 列表查询**必须**具备过滤、分页、cursor 或明确的小表上限。
- API 查询**必须**显式选择所需字段，密码、令牌和内部备注等敏感字段禁止默认查询。
- 普通查询**必须**排除软删除记录，关系查询必须同时排除已软删除的关系记录。
- 标准关系读取**必须优先**使用 ORM relation；只取关联 ID 时使用引用 populate。
- to-one 关系**可以**按结果规模选择 JOIN、select-in 或独立查询。
- to-many 查询**必须**使用 select-in 或明确的受控 JOIN，并同时限制父结果和集合数量。
- 只有特殊聚合、独立分页或 ORM 无法清楚表达时，才可以手工查询 pivot。
- to-many 需要独立分页时**必须**使用独立接口或集合查询。
- **禁止**N+1 和循环加载关系。
- 每父记录前 N 条**必须**使用 per-parent limit、窗口查询或独立接口，禁止用全局 limit 代替。
- 分页排序**必须**稳定，并包含可唯一确定顺序的兜底字段。
- 模糊查询禁止假设普通 B-tree 可以优化 `%keyword%`。

## 新增

- 新增关系记录前，Service **必须**校验关系对象存在、有效且未软删除。
- 多表新增**必须**使用显式事务。
- 创建子记录时**必须**按并发要求锁定父记录，并与删除父记录保持一致的锁顺序。
- Service **必须**执行唯一性预检查和业务错误转换，数据库唯一约束负责最终并发兜底。
- **禁止**依赖 cascade persist、集合方法或嵌套对象完成新增。
- 事务**必须**保持短小，事务内禁止 HTTP、Redis、MQ、文件系统和用户等待。

## 更新

- 更新操作**只能**修改 DTO 明确允许的字段，不可修改字段禁止出现在更新 DTO 中。
- 单 Entity 更新**必须**使用变更追踪和 `flush()`。
- 批量更新**可以**使用 `nativeUpdate()`，使用前必须确认业务不依赖 Entity 生命周期逻辑。
- **禁止**循环逐条 `flush()`。
- 修改唯一字段时**必须**重新检查冲突，并保留数据库唯一约束兜底。
- 修改关系范围时**必须**重新校验关系对象，并按并发要求加锁。
- 关系变更**必须**由专用关系 Service 显式完成，禁止通过 ORM Collection 隐式写入。

## 删除

- 业务数据默认使用软删除，删除后的记录禁止被普通查询返回。
- 纯关联记录删除**必须**使用物理删除；业务关联是否软删除由其业务字段和审计要求决定。
- 删除父记录时，Service **必须**显式处理关系记录和子记录。
- 多表删除**必须**在同一事务中完成，并明确删除顺序和锁顺序。
- **禁止**cascade remove 和 orphan removal。
- 重复删除**必须**具备幂等语义或返回明确错误。
- 无物理外键时**必须**定期检查孤立数据。
- 关系清理失败**必须**返回明确错误，禁止静默忽略。

## 检查清单

- [ ] Entity 使用统一定义方式，API 未直接返回完整 Entity。
- [ ] 数据库没有物理外键，关系没有非空 cascade 和 orphan removal。
- [ ] ORM 关系用于标准读取，关系写入由专用 Service 显式完成，业务代码没有集合修改或嵌套 `em.assign()`。
- [ ] 纯关联表使用复合主键和物理删除，业务关联才保留独立生命周期。
- [ ] 查询显式选择字段，并排除当前表和关系表的软删除记录。
- [ ] 列表和 to-many 查询具备稳定排序及数量边界。
- [ ] 代码没有 N+1、循环加载关系或循环 `flush()`。
- [ ] 新增前校验关系对象，并使用唯一约束处理并发竞态。
- [ ] 多表新增、更新和删除使用短事务，事务内没有外部 IO。
- [ ] 更新只修改 DTO 允许字段，关系更新只写差异，批量更新不依赖 Entity 生命周期逻辑。
- [ ] 删除由 Service 显式处理关系记录、子记录、顺序和锁。
- [ ] 索引覆盖实际查询且没有重复，软删除唯一约束只覆盖有效数据。
